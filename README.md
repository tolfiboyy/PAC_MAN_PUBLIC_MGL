# Pac-Man

## Description

This project is a complete Pac-Man game written in Python with Pygame. The maze is generated with the assigned external **A-Maze-ing** package and is not generated by our own code.

The game includes:
- at least 10 levels;
- a fixed seed for the first level and random mazes for the following levels;
- pacgums and super-pacgums;
- four ghosts with different chase behaviours;
- lives, score, level timer and level progression;
- persistent highscores;
- menu, instructions, pause, game-over and victory screens;
- a cheat mode for peer review;
- a PyInstaller packaging workflow.

The project is split between the application layer (`app/`) and the gameplay layer (`game/`).

## Instructions

### Requirements

- Python 3.10 or later
- `make`
- Linux environment recommended for the provided package build

### Install

```bash
make install
```

This creates the `PacmanEnv` virtual environment and installs the dependencies from `requirements.txt`, including the provided `mazegenerator` wheel.

### Run

```bash
make run
```

The default configuration is `config.json`.

To use another configuration:

```bash
make run CONFIG=my_config.json
```

Equivalent direct launch:

```bash
PacmanEnv/bin/python3 pac-man.py config.json
```

The program expects exactly one JSON configuration file.

### Lint

```bash
make lint
```

Optional strict check:

```bash
make lint-strict
```

### Package

```bash
make package
```

This uses `pacman.spec` and generates the distributable build under `dist/pacman/`.

### Controls

- Arrow keys: move Pac-Man
- `ESC` / `PAUSE`: pause the game
- `END`: end the current game
- `TAB`: show/hide the cheat sheet
- `F1`: increased player speed
- `F2`: invincibility
- `F3`: freeze/unfreeze the level timer
- `F4`: skip the current level

Menu navigation uses the arrow keys and `ENTER`.

## Configuration

The configuration file is JSON and also supports full lines beginning with `#` as comments.

Main keys:

| Key | Safe default | Description |
|---|---:|---|
| `highscore_filename` | `highscores.json` | Highscore file path |
| `lives` | `3` | Starting lives |
| `pacgum` | `42` | Number of regular pacgums requested |
| `points_per_pacgum` | `10` | Points per pacgum |
| `points_per_super_pacgum` | `50` | Points per super-pacgum |
| `points_per_ghost` | `200` | Points per edible ghost |
| `seed` | `500` | Fixed seed used for level 1 |
| `level_max_time` | `90` | Time limit per level in seconds |
| `level` | 10 default levels | List of level dimensions |

Invalid or missing values are replaced or clamped to safe values with a clear message. Unknown keys are ignored by the loader.

## Highscore

Highscores are stored as JSON and loaded when the application starts.

Rules:
- maximum 10 entries;
- names are 1 to 10 characters;
- names may contain letters, digits and spaces;
- scores must be non-negative integers;
- invalid entries are ignored;
- file errors are handled without stopping the game.

At the end of a normal game, the player can enter a name and save the final score. Runs where a cheat was used are intentionally not saved to the highscore table.

## Maze Generation

The project uses the assigned `mazegenerator` package exactly as an external dependency. The original wheel is kept at the repository root and installed through `requirements.txt`.

Level generation rules:
- level 1 uses the configured fixed seed;
- subsequent levels ask the generator for a random maze;
- `PERFECT` is set to `False` for Pac-Man-compatible corridors;
- the player starts near the maze centre;
- the four ghosts and the super-pacgums start in the four corners.

Our code adapts to the generator interface; the generator itself is not modified.

## Implementation

Main gameplay choices:
- entities move on maze cells while their rendered positions are interpolated for smooth movement;
- requested player turns are buffered until the turn becomes possible;
- collisions use the distance between rendered positions;
- ghost paths are computed with breadth-first search;
- the four ghosts use different target strategies (`direct`, `ahead`, `vector`, `distance`);
- frightened ghosts flee and edible ghosts can be eaten for points;
- score and remaining lives are stored in `GameSession` and persist between levels;
- cheats are also stored in `GameSession`, so active cheats survive level changes.

To respect the graphical-library constraint, directional sprites are stored as separate images instead of being rotated at runtime.

## General Software Architecture

```text
pac-man.py
    |
    v
app/
    config.py          configuration loading and validation
    app.py             application loop and state transitions
    state.py           menu/game/pause/end/highscore states
    game_session.py    data shared across levels
    highscores.py      persistent score handling

    |
    v
game/
    movement.py        maze movement rules
    player_logic.py    player target/render updates
    ghost_logic.py     ghost AI and frightened/respawn logic
    pathfinding.py     BFS pathfinding
    collisions.py      player/ghost collisions
    collectibles.py    pacgums and level completion
    level_logic.py     external maze integration and level setup
    rendering.py       maze/entities/HUD rendering
    cheats.py          cheat state
    assets.py          sprite/background loading
```
